# Design: bounded sequential corpus run

## Context
PR #19 merge was confirmed at 44b4dec55c0b50ff0fbecede326778f97255ff03.
Implement one in-memory pass under the approved evaluate-text-pdf-extraction plan.
Three repetitions, scoring and durable reports belong the eventual comparison.

## APIs and records
Expose `run_corpus(workspace_root: Path, corpus_path: str, limits=None)`.
`RunLimits` has finite positive wall_seconds <=600, exact positive integer
output_bytes <=50 MiB and exact validated WorkerLimits. Defaults retain approved
worker ceilings. Invalid profiles fail before source loading/launch.

Use load_corpus to validate every entry and capture all bytes before any worker;
preserve manifest order, hashes, metadata and source bytes. Public callers cannot
supply unverified LoadedFixture objects as accepted snapshots.

Frozen `FixtureRun` has specification, result (TXT/PDF worker result or None),
output_bytes (observed combined bytes, 0 for never launched, None if interrupted
before observation completes), unfinished_reason (RunStatus or None).
Frozen `CorpusRunResult` has status, fixtures and output_bytes (sum only when
every row's observation is known; otherwise None). Model constructors are value
containers, not validity/authenticity boundaries. COMPLETE describes a completed
schedule, including failed files, and never a successful comparison.

RunStatus names COMPLETE, TIME_LIMIT, OUTPUT_LIMIT, UNSUPPORTED_ENVIRONMENT,
CANCELLED and CLEANUP_FAILURE. Give every selected fixture one row: observed
worker outcomes for finished calls, explicit reasons for unstarted/interrupted work.
Source expectations remain independent and are not promoted to extraction results.

## Transport accounting without changing worker APIs
Retain the existing sole exact Popen and completion/lifecycle semantics. Add an
internal optional output observer to run_command/capture_pipes. Notify it for
every bytes chunk actually read from stdout or stderr, including the one overflow
probe byte, before checking the cap. Capture discards stderr as before.
A focused mutable counter feeds internal observed TXT/PDF execution functions;
they return a frozen WorkerExecution[result, output_bytes]. Existing public
run_text_worker/run_pdf_worker continue returning their existing result types.
No response reserialization or estimated byte count substitutes for observations.

The run clamps each worker combined cap to its remaining aggregate allowance.
A worker can read at most one additional detection byte; it is counted, not
hidden. Aggregate counts may therefore exceed their cap by exactly that probe
byte, after which no further worker starts. This bounds observed pipe bytes,
not all child-generated bytes, Python object memory or a persisted report.
Per-file failures still consume their measured transport allowance.

## Ordering, guards and deadlines
Start the monotonic run budget before validated corpus loading. Before the first
worker require Linux waitid/WNOWAIT and the existing bounded loopback-only
topology guard. A connected or unavailable environment produces all unfinished
rows without launching even TXT. Docker --network none supplies the boundary;
the API does not create it. Use only the trusted non-root image, Soulkiller mount,
no added privileges/socket/external services and a stable namespace.

Dispatch fixed TXT baseline or pypdf worker sequentially. For PDF use each
fixture's independently declared page_count as its per-worker page cap:
under-declared larger PDFs yield explicit page_limit rather than silently exceed
the corpus's declared page budget. Actual/declared disagreements remain findings.
Do not fall back, compare expected outcomes or discard failed rows.

Before every launch clamp worker wall time to min(per-worker cap, remaining run
deadline), and output bytes to min(per-worker cap, remaining run bytes).
After return check actual deadline/bytes; retain the finished outcome and stop
unstarted work when exhausted. Exact output exhaustion after the last finished
row can remain COMPLETE; a detected aggregate overflow cannot. A worker reporting
unsupported_environment stops the run. Other per-file failures leave independent
fixtures eligible while aggregate guards remain available.

Synchronous corpus reads/process creation cannot be preempted by this scheduler;
elapsed time is checked when they return. Cleanup retains its existing bounded
wait, which can extend return time beyond the scheduling deadline. No absolute
parent-process hard-stop or benchmark timing guarantee is claimed.

## Interruption and cleanup
KeyboardInterrupt after corpus acceptance is re-raised as CorpusRunCancelled,
a KeyboardInterrupt subclass with immutable .result. WorkerCleanupError is
re-raised as CorpusRunCleanupError, a subclass preserving the existing catch
contract with .result. The current call is unfinished/unknown-byte count;
earlier completed observations remain available, later rows are never launched.
Cleanup failure takes precedence, and no uncertain cleanup permits continuation.
These are in-memory records only; caller exit/crash does not provide durability.
