# Proposal

## Why

After merging PR #6, the maintainer requested DevOps/DevSecOps integration with
every implemented component, a 70% coverage minimum and a GitHub Pages docs site.
These commitments need durable roadmap and issue tracking before implementation.
The maintainer also clarified automatic-memory content and deletion behavior.

## What Changes

- Record local/CI quality and security requirements, including Gitleaks, Hadolint,
  conditional language analysis, web ZAP and the coverage minimum.
- Propose fast PR gates and bounded deeper tag/manual checks with no mandatory
  paid account, preserving local devcontainer rules.
- Plan a styled static Pages site using Actions deployment, compare Docusaurus
  and stable VitePress, and preserve authoritative English Markdown/OpenSpec.
- Create the authorized future implementation issues #7 and #8, update roadmap,
  README, contribution/agent instructions, OpenSpec context and CHANGELOG.
- Record explicit statements/faithful summaries as permitted memories, with
  attribution and no inferred preferences; deletion removes memory/derivatives,
  retains history and prevents automatic regeneration.
- Record confirmed review of the previous framing separately from unresolved
  product, resource and architecture choices.
