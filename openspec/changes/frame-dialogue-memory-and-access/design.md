# Design

## Scope and status

This packet records maintainer answers from 2026-10-04 and compares access options.
Confirmed intent, engineering proposals and unresolved choices remain distinct.
Review accepts the record and comparison; it does not authorize a runtime,
provider, endpoint, source-data transfer or E1-E9 experiment.

## Decision boundaries

Missing evidence yields explicit uncertainty. Contradictions stay visible with
sources; recency and import order do not automatically select truth.
Speaking style can evolve through explicit changes that can be inspected and
deleted. Update triggers, correction, composition and deletion effects still need
an operational contract. No manual memory-save/activation gate is introduced,
and inferred preferences or model inventions do not become established facts.

Shared recall within a persona and management permission are separate concerns.
A conversational name is not verified identity; accounts need not imply cloud
hosting. Compare trust boundaries and costs without adopting an access model.

## Review and validation

Use invented Inez/Corin examples, with source and conversation provenance distinct.
The acceptance matrix is proposed, not executable tests or measured behavior.
Link the existing evaluation plan instead of duplicating its general comparison.
Validate OpenSpec, local Markdown targets, YAML, whitespace, staged secrets and
unchanged LICENSE inside the devcontainer. Apply the existing foundation CI to
the PR; report its actual outcome separately from document validation.
